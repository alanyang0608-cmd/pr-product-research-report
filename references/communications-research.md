# 传播研究流程

用于公开传播复盘、近期内容研究、平台舆论观察及传播方法提炼。回答“发生了什么、为什么这样表达、如何承接用户、证据能支持多大结论”。不把几篇官网文案解读包装成多平台研究。

## 1. 固定研究边界

- 确认产品主体、研究用途、起止日期、时区、重点市场与平台。沿用已确认范围；“最近几个月”未给具体日期时，可提出近三个月的明确起止日，并继续不依赖答案的产品识别与背景采集。没有回复且时间范围不构成硬约束时，说明所采用的默认范围。
- 主研究期与窗口外背景分开。更早的品牌活动和首次发布可解释当前策略，但不进入本期声量、样本分布或热门排名。
- 先看当前可用的公开检索和平台渠道。有可用网络研究 skill 时按其路由执行；不要把一次任务的命令、登录状态或具体平台清单固化为前提。某渠道失败时记录原因，继续可用来源；未读到不等于没有传播。
- 若用户要“全面”，优先覆盖不同舆论场及相反体验，而不是只多收同源新闻：官方、创作者教程、用户讨论、专业社区、媒体报道、机构课程或伙伴内容。覆盖强弱须呈现。

## 2. 先做证据库，再写报告

### 采集顺序

1. **官方与关键事件**：官网、更新日志、公告、公开活动和发布报道，建立产品与传播事件候选时间线。
2. **分平台搜索**：产品全名与必要别名，组合“教程、体验、工作流、费用、失败、更新、发布”等实际相关词；按研究期筛选。搜索结果和聚合文章用于发现原始链接。
3. **高互动与典型内容**：核验候选热门内容，同时保留有具体任务、反馈或承接方式的中小样本。不要只收赞同内容或把搜索首屏当成总体排名。
4. **原文与指标复核**：重要判断、高互动榜首及数字冲突优先回到原帖、公开元数据或实际页面核对。无法读取原帖时如实记录已取得的层级，不补全未见的内容。
5. **迭代补缺**：检查事件是否只有宣传稿、平台是否只有培训号、评论是否只有“求资料”。补能改变结论的证据；限制重复转载、重复搜索和失败重试，不设虚假的全平台完成标准。

### 建议字段

按任务规模裁剪，但关键日期、来源、口径和排除理由应能追溯。Markdown、图表、热门列表从同一份结构化数据生成。

| 字段 | 含义及注意事项 |
| --- | --- |
| `id / product / platform / url` | 稳定编号、已确认产品身份、实际来源平台、原始内容链接 |
| `title / author / author_type` | 页面标题、署名和主体性质；官方、媒体、创作者、用户等身份按证据确认 |
| `published_at / published_basis` | 刊发时间及依据；不明确时留空，不拿编辑日或活动日冒充 |
| `event_at / captured_at` | 事件发生时间与采集时间，单列；说明时区 |
| `evidence_level / evidence_note` | 已读正文、视频已看片段、简介和评论、索引内容、只有链接等实际获取程度；可记录已核验片段时间点 |
| `scope / exclusion_reason` | 期内样本、仅活动节点、背景、待核线索、排除等状态及理由 |
| `content_type / theme / event_cluster` | 内容形态、人工归纳主主题、同一事件的关联；同事件不一定同稿件 |
| `origin_id / canonical_url` | 有依据时关联同源转载；没有证据不猜原稿或合并独立内容 |
| `metrics / metrics_as_of / metrics_basis` | 播放、阅读、赞、藏、评、分享等分字段保存；采集或索引快照的时间、来源、约数说明 |
| `claim / feedback / sponsorship` | 此材料支持的判断、具体反馈摘要、商业关系是否已核实 |

可用 `records / support / leads / excluded / coverage` 分开管理样本、支持文档、待核线索、排除记录和平台覆盖。无须机械使用这套字段名，但输出中应能区分这些性质。

### 容易误算的情况

- 核对当前标题、原始发布时间与产品身份：旧视频后来改标题、聚合页错配其他产品，都可能产生虚假的“近期爆款”。不符合时间或主体的条目从排名剔除，保留排除原因；不凭时间异常就断言造假。
- 账号名称含“官方”、名人名号，或文章位于某企业社区域名，都不能单独证明官方归属。合作未核实就是未知，不自动算品牌投放，也不自动算纯自然口碑。
- 原生页面、转载页、搜索索引和 AI 聚合摘要不是同一证据。具体索引文字可作为有限证据并标明来源；未读全文不声称读完原文。AI 摘要里的数字不能独立作为热门榜或增长结论。
- 播放、独立用户、访问次数、月活、评论条数分别记录。一个人可能多次观看或同时点赞收藏，不能把互动相加成独立曝光。
- 未公开指标用 `null` 或空值；页面显示“万”的数值保留约数说明。公共累计计数不是研究期新增量，也不能反推发布日计数。多次快照的增量还需留意删帖、计数修正和缓存。
- 同一公告被多家媒体转述，可计为多条传播样本，但只能当作一个发布事件；指标亦不能据此证明多个独立信源验证了效果。
- 发布时间、活动时间、版本生效时间分别用于对应时间线。首次正式发布不一定等于首次可用或首次上架。
- 目的性样本的时间图只称“已收录内容分布”；空白周不代表零传播。没有可比监测、随机抽样或完整评论时，不画总体舆情比例或估算全网声量。

## 3. 从材料推导策略

先写几条最重要的判断，每条连接“观察 → 解释 → 局限”。不要堆完新闻标题便称深度分析，也不要把研究者的阶段归纳写成品牌内部计划。

可按以下问题展开，取证据充分且符合用户目的的部分：

| 维度 | 要解释的机制 |
| --- | --- |
| 节奏 | 哪些产品升级、权益变化、活动或媒体议题持续提供参与理由？哪些是并行发生，哪些有明确先后关系？阶段数量随材料确定 |
| 叙事 | 对谁说、承诺解决什么、用什么任务或成果证明？表达是否从功能推进到用户作品、组织价值或平台身份？不要预设所有产品都走同一路线 |
| 内容与承接 | 标题和开头吸引什么需求？演示如何组织？看完后去哪里：下载、扫码看成品、做同款、领资料、进群、交作业？区分品牌承接和作者获客 |
| 平台分工 | 各平台实际出现哪些内容、谁在生产、互动是什么性质？先有证据再归纳，不套“某平台必然种草、某平台必然转化”的模板 |
| 舆论与体验 | 按具体任务比较承诺与感受。找上手困难、费用误解、可靠性、成果是否可用等有信息量的问题；几条意见不外推为用户比例 |
| 效果与归因 | 哪些结果有可比数据，哪些只表明关注、收藏或求资料？独立规模报告可作背景，但没有归因数据就不能证明某活动带来增长 |
| 可借鉴方法 | 提炼可执行的内容、演示、承接与后续选题建议；说明成立条件。研究建议与研究对象已执行的动作分开 |

高收藏可以支持“可能有留待学习的价值”，不能证明实际跟做和留存；“求资料”评论可能是资料交换或课程引流，不等于产品认可。账号发布密集或多人使用同一话题，也不能单独证明付费排期。

## 4. 高影响内容怎样交付

- 有公开可比指标的平台，分别按同平台、同指标排序，并写“本次可核验样本内”。保留作者、日期、链接、指标、采集口径和为什么值得看。说明没有覆盖的渠道，不能声称全网最大。
- 对没有可比较阅读量的报道，提供“关键阅读”或“策略价值精选”；用议题、采访和证据价值解释选择，不造流量名次或混合影响力分数。
- 重要视频可补已核验的片段或内容结构、演示方式、行动引导及评论例子。只读到简介就只分析简介；未经许可不为报告下载整段视频。
- 优先就近放短来源编号链接，完整标题在来源索引保留，避免正文被反复出现的长标题打断。反馈以短转述为主，直接引语应准确并符合来源限额。

## 5. 形成报告与数据交付

完整传播研究可采用：**产品是什么与研究范围 → 核心判断 → 时间线与叙事 → 分平台内容及代表案例 → 可观察效果与限制 → 高互动链接和关键阅读 → 借鉴建议 → 方法与来源**。读者越陌生，开头越需要用具体任务解释产品；不必照搬完整产品评测结构。

用户要求深度报告且未指定长度时，可按 3000 字以上正文组织，但以分析充分为准；简要传播问题不强制长文。计算正文篇幅时去掉来源索引、重复标题和链接地址，不靠引用堆字。

需要数据采集、分析、可视化三个阶段时，交付可复查的结构化数据、独立 Markdown 报告和 HTML 看板；看板完整嵌入正文或提供明显的完整报告入口。文件包仅包含实际交付内容，不夹带账户信息、依赖目录或未授权的全文素材。

交付前检查关键日期与产品身份、榜首指标、排除条目、跨文件数字一致性及覆盖缺口。报告能够说明“哪些已知、哪些推断、哪些未知”即有价值；不要用虚构的全面性补足无法访问的平台。
