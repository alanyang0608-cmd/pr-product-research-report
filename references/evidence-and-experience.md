# 证据、界面与用户反馈

## 研究底稿

每条重要材料至少记录：产品身份、要支持的说法、来源链接、来源类型、发布日期或访问日期、可用范围和限制。记录实际观察，不把未打开的搜索摘要当成全文已核实。

| 材料 | 适合证明 | 不能单独证明 |
| --- | --- | --- |
| 官网、说明文档、更新日志 | 官方定位、能力描述、发布状态 | 普遍使用效果、可靠性与市场成功 |
| 官方截图、演示视频 | 界面结构、演示路径、所展示的结果 | 任意用户都能复现、端到端成功率 |
| 应用商店评价、公开使用记录 | 某个用户的体验和使用问题 | 整体用户共识、评价者身份真实性 |
| 官方精选用户证言 | 品牌选择呈现的体验主张 | 独立评价、全面口碑 |
| 媒体实测 | 其披露条件下的观察 | 未测试场景与长期效果 |
| 融资、下载量和热度报道 | 对应口径与时间内的事件或指标 | 付费意愿、留存、服务质量 |

## 产品识别

同名候选按官网、主体、图标、商店开发者、产品描述相互核对。信息仍有分歧时保留分歧，不将不同候选的定价、评论和界面拼在一起。

用户没有链接时先查找最符合上下文的候选；在报告中用简短脚注写清本次研究的是哪一个。不能确定就将该产品暂列为待确认，同时完成其他产品。

价格标明币种、周期、地区、试用条件与查询日期；“起价”“按年折算月费”与月付价区别表述。不要用过去版本功能替代当前状态。

## 新旧资料与冲突口径

- 先判断资料是否谈论同一产品、版本、地区和购买渠道，再比较更新时间。当前条款和购买页可以纠正旧发布文中的测试期说明，但不同渠道的价格不应硬合成一个价格。
- 商店概览、完整评论页与缓存页面可能显示不同评分和样本量。写清采用哪一页、哪个地区及查询日期；不平均、不相加，也不凭显示差异推断口碑上涨或下跌。
- 已保存并核查过的材料可以继续使用，保留当时的查询记录；本次未重新取得的页面不写成“刚刚再次验证”。相对日期如“1 天前”不要脱离页面查询或抓取时间换算成确定发布日期。
- 样稿和搜索摘要用于发现线索。重要体验与争议需要读到支持该说法的原文；无法核实就降级为线索、注明缺口或省略，不用另一段摘要补成完整故事。

## 界面与视频获取

1. 优先查官网演示、帮助文档、官方商店和可追溯的实测材料。
2. 打开并检查图像；视频观看相关片段，记录时间点，核对旁边的说明确实由画面支持。剪裁或转码后，以交付文件重新检查时长、关键帧与跳转时间；不要只照抄参考稿的时间标签。
3. 用可用的原始媒体、授权截图或允许的嵌入方式呈现。遵守工具权限和平台限制，不绕过媒体展示限制下载内容，不为获取素材关闭证书校验。
4. 标清“官方演示”“应用商店截图”“作者实测截图”“流程示意”等性质，并保留来源。
5. 页面截图应避免无关的个人账号信息。裁剪、加标注或压缩不应改变画面所表达的事实；必要时注明局部展示。

素材请求设置有限的超时与重试；先检查类型、大小与时长，避免为一张说明图下载整段大型视频。获取失败时改用来源入口或自绘说明流程，明确哪些画面未能取得。已经有一组清晰的核心交互证据后，通常无需无限增加截图。

官网图片暂时不可用时，可在产品身份确认后，检查同一产品的官方商店、帮助文档或用户提供的本地素材。选择有助理解操作的画面，先核实归属和内容，再替换临时示意。其他来源不是绕过访问或媒体限制的手段；某条路径失败也不能被写成“该产品没有界面”。

自绘流程可以写“依据官方说明整理”，不得使用会让读者误认成真实截图的标签。生成式图像不用于伪造产品 UI 或用户实测证据。

## 反馈查找与写法

在身份确认后，用产品全名、官网域名或开发者名称搭配 review、experience、discussion 等查找公开反馈；按产品实际社区选择平台。查阅原始内容，留意版本、时间、任务、推荐码、赞助或利益关系。

推荐呈现方式：

> **某项任务中的体验**：概括用户认为有效的地方，以及其提到的限制。——某平台的用户记录，日期；附原文链接。

译文或转述要明确性质，不把概括放进引号冒充原话。引述保持简短，遵守来源版权限制。反映使用过程的细节比“太棒了”“未来已来”更有价值。

- 评分要带地区、样本量和查询时间；不跨地区或同名应用相加。
- 优先保留会改变使用感受的细节，如调整条件后是否记得、后续跟进是否及时、等待是否影响任务、用户为什么停止执行。同一作者在不同场景的赞许与失望可以并列，不必凑成正负各半。
- 媒体观点若没有使用过程，作为分析意见，不列作亲测。
- 官网证言可作为补充，紧邻标注“官网精选评价，非独立样本”。
- 取得投资者邀请、推广合作或疑似团队成员的署名等关系，应随反馈交代；身份未核实时不猜测其职位，也不当作已确认的独立口碑。
- 没有可信用户记录时写“本次未找到足以核实的独立使用反馈”，可接已找到的官方演示，不把空白补成虚构评价。

## 分析边界

用“官方介绍”“演示显示”“该用户记录”“据此可以推测”等自然语句区分依据，无需在每句堆标签。

个人背景的长期积累、实际准确理解、跨服务可用性是不同层次；只有看过相应证据才下结论。工具连接、任务规划、向用户建议和真正执行也分别表述。

不要复述用户提供的内部指标、规划或未公开伙伴信息到公开渠道。为用户项目做关联分析时，用已获授权的材料并标明性质；不把自己的对比分析冒充研究对象官方表态。
