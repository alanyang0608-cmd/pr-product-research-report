# HTML 呈现与交付检查

## 先定内容，再定样式

用户指定视觉优先；完整报告无指定风格时，可用白灰科技风：白色与浅灰背景、清晰黑字、克制蓝色强调、适量留白与圆角。不要照搬品牌标识制造官方归属感。

首屏必须有实际产品介绍。标题、导航和导语应简洁，避免大幅装饰挤掉内容。多个产品可用总览卡片，点击后进入对应单品；窄屏自然换行。

主内容保持适宜行宽。事实条、界面、反馈和分析有层次，但不必把每句话放进一张卡片。

白灰科技风可以用紧凑导语、产品总览、独立单品区和浅色过渡区建立节奏。章节标题和短阅读路径应帮助定位，不能让读者先滚过一整屏装饰才见到产品。在手机上按阅读顺序重新排版，避免只把桌面整体缩小。

## 值得使用的交互

- 产品总览跳转与清楚的章节导航。
- 截图放大，支持键盘关闭与清晰的关闭按钮，关闭后焦点回到触发处。长截图允许滚动看清文字，不把放大图再次压缩到整张塞进屏幕。
- 图组切换时同步更换图片、中文解说、画面性质和来源；步骤切换有明确选中状态，每一步都包含动作或结果。
- 视频由读者主动播放，可提供经过核实的关键时间点；保留暂停控制和一张有信息的封面。不能播放时仍可读到关键帧或文字流程。
- 比较维度较多时提供清楚的分组或两层切换，先看使用差异，再进入背景、执行与控制。
- 详细来源、研究边界等展开项。

只做有助理解的交互。不要用装饰性动画、复杂轮播或默认自动播放增加阅读负担。静态内容应在脚本失效时仍能阅读；正文不能必须点击许多次才能获得。

折叠用于控制阅读深度，不隐藏产品最重要的定义、流程概要与结果。需要脚本才隐藏的图组和步骤，可先让正文可见，再逐步启用切换；打印时展开必要内容，视频以关键帧与解说承接。

## 媒体可用性

已合法获得并允许本地使用的素材，可内嵌或随 HTML 打包；资源路径保持可携带。单文件体积过大时采用资源目录与 zip，不为追求单文件牺牲清晰度或加载速度。

在线嵌入要检查实际展示，保留来源链接和失败时的文字说明。不得通过下载绕过媒体展示限制。仅外部链接需要联网时如实说明，不能因此把整份报告称为完全离线可用。

每张图应有替代文本、画面性质、中文注解和来源。真实截图里的文字不可小到无法辨认；尽可能提供放大入口。视频压缩后检查时长、画面、字幕及重要步骤是否完整。内嵌素材时核对实际媒体类型，不能只依赖原文件扩展名。

## 交付前验证

先做内容核对，再做必要的页面检查：

- **首屏**：实际浏览器打开后，能否马上看见产品定义和用途？
- **桌面与窄屏**：有无横向溢出、错位、过小文字或导航遮挡？宽表格在自己的容器内滑动，不拖宽整页；事实条及其来源在窄屏上仍连贯。
- **媒体**：实际打开每组采用的图，切换后能否加载并对应解说？视频能否播放、暂停，并从标记时间跳转到说明的片段？惰性加载图片需进入视口或触发后再判断，不能只凭初次加载状态判为损坏。
- **交互**：章节锚点、图组、步骤、比较分组、展开与关闭是否可操作，焦点是否清楚？按页面实际包含的交互检查，不为不存在的组件增加工作。
- **事实**：界面注解是否对应画面，反馈是否标明来源，分析是否超出证据？
- **可携带性**：从交付目录打开仍能使用，压缩包包含必要资源；不引用临时目录。

静态检查只能证明结构，不能代替实际渲染查看。未能运行浏览器或核实媒体时说明具体未验证项目，避免声称全部通过。低影响排版调整不需要建立繁重的测试工程。

复用参考 HTML 时留意多段样式与移动端覆盖顺序。最终以浏览器实际布局为准；修改后复查受影响部分，不只检查新增样式文本。预览图从最终文件重新取得，交付文件与用户正在打开的版本保持一致。

修改已有报告时保留可恢复的旧版，交付清楚命名的新版本；用户正打开的文件可同步更新，避免看到旧内容。最终给可直接打开的报告链接；需要分享离线素材时附文件包。不要自动发布网站、上传用户材料或创建外部账号。
