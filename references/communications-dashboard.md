# 传播 Dashboard

用于将传播研究转成可浏览、可追溯的 HTML。与 [传播研究流程](communications-research.md) 及 [HTML 呈现与交付检查](html-delivery.md) 配合，不承担额外采集或编造指标。

## 阅读顺序与交互

首屏先给产品的直白定义、研究日期和最重要判断。少量指标卡必须标明单位与范围，例如“有刊发日的样本数”“某平台样本内最高收藏”。样本量不是研究成果好坏的评分，缺失指标不显示为零。

适合完整看板的内容入口可组合为：

- **总览**：读者先认识产品，再看到核心传播主线及证据入口。
- **传播节奏**：按阶段切换叙事、动作、关键节点与对应内容；明确阶段是研究归纳。刊发日与活动日分别标记。
- **平台与热门**：切平台后只提供该平台可比较的指标；新闻精选与量化热门分开。覆盖说明显示已取得什么和还缺什么。
- **证据库**：按关键词、日期、平台、主题筛选，显示结果数量、空状态、重置及导出；详情可读证据层级、指标口径、实际日期依据和原文链接。
- **深度报告**：完整正文、简短引用链接、来源索引，允许下载 Markdown；必要时打印。

入口数量随材料裁剪。没有指标就不放空榜单；没有时间跨度就不做装饰性趋势图。用户只需阅读型 HTML 时，不强制实现整个分析后台。

## 图表和数据规则

- 报告、图表、热门表、证据详情共用一个数据源。样本记录与背景、活动、待核线索、排除项分开，确保筛选与统计使用同一纳入规则。
- 时间图注明“收录样本分布，非全网声量”，标明日期粒度与窗口首尾不完整的月份或周。只有真实可比监测数据才能展示声量趋势。
- 主题图说明为人工编码，每条赋一个主主题或明确多标签口径；不要把主题占比称为情绪或用户占比。
- 排序所选指标同步影响图表、表格数值、标题和单位；未公开值不参与排序。“最高播放”和“最高点赞”分开，原始值可从详情读取。
- 筛选的作用范围在界面说清楚。只筛证据区时，总览图必须继续使用全部有效样本；全局筛选则在各视图清晰显示当前条件。不要让跨页残留条件悄悄改变总览结论。
- 不同证据层级和口径可在详情展开；涉及热门结论的关键边界要在榜单旁直接可见。

## 单文件与技术选择

用户指定 React + Recharts 时确实使用它们；没有指定时选择与交付需求相称的实现，不锁定某次报告的库版本。若当前环境要求使用建站技能，按其流程处理，同时保留用户指定的独立文件交付，不擅自扩展发布范围。

用户要求可离线阅读的单文件时，将实际使用的依赖、样式、数据及正文打包内置，不把依赖 CDN 的页面称为离线文件。外部原文链接需要联网应注明。脚本不可用时保留可读的静态报告；交互启动成功后再隐藏静态回退，避免初始化失败后整页空白。

优先使用本地已可用依赖。需要新依赖时按环境权限取得，采用当前官方文档或实际库类型定义确认 API，不复制旧报告的版本号。文件能直接打开，不引用临时服务器或工作目录才能运行的资源。

界面使用读者能理解的词；采集程序名、构建过程等放在必要的交付说明中，不占首屏。保留必要开源许可证。不把未经授权的原文全文或远程媒体塞进单文件。

## 交付验证

在实际浏览器检查页面所包含的关键路径，改动后只复查受影响部分：

1. 桌面和窄屏都能读到定义与主要结论；宽表格只在自己的容器滚动，图表尺寸有效。
2. 阶段切换后节点与内容对应；平台和指标切换后图表与表格一致。
3. 组合筛选、日期边界、零结果和重置正常；输入过程中不会因组件重建而失去焦点。
4. 详情可打开、关闭并返回触发处；原文链接与证据编号对应。
5. 导出使用当前筛选和正确字段；完整报告与独立 Markdown 一致，中文 CSV 的编码适合表格软件。
6. 从最终交付目录打开可用；单文件的脚本和样式没有遗漏的外部依赖，压缩包包含所需交付文件。

不以“页面能打开”替代交互验证，也不为简单排版建立庞大的测试工程。不能验证的项目如实说明。交付主看板、Markdown 和必要数据包；预览与交付文件保持同一版本。
